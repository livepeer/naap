Orchestrator Leaderboard · NaaP

Signer Bundle Discovery — Infra Config

Point each remote signer at the matching discovery plan (or bundle alias). Daydream → BYOC/tool orchs. pymthouse → Live Runner orchs. Same [{ "address" }] contract — choose the URL, not a matrix of flags. Plans appear at /orchestrator-leaderboard/plans like any other public plan.

1. The model (one sentence)

Discovery URL selects the orchestrator plane. The signer stack you already run decides payment; these endpoints only answer “which orch URIs should I dial?”

Daydream BYOC plane

Plan naap-default-daydream-byoc
…/plans/{id}/python-gateway

alias …/bundles/daydream-byoc/python-gateway

Returns BYOC + tool hosts, e.g.
byoc-staging-1.daydream.monster:8935
tool-staging-1.daydream.monster:8935

pymthouse Live Runner plane

Plan naap-default-pymthouse-live-runner
…/plans/{id}/python-gateway

alias …/bundles/pymthouse-live-runner/python-gateway

Returns Live Runner hosts, e.g.
liverunner-staging-1.daydream.monster:8935 

SDK / gateway node
  │  DISCOVERY_URL = one of the two endpoints below
  ▼
NaaP  GET /bundles/{slug}/python-gateway
  │  Bearer gw_…   +  SIGNER_BUNDLE_DISCOVERY_ENABLED=1
  ▼
[{ "address": "https://…" }]  →  dial orch  →  sign via your remote signer
Keep it simple: do not mix planes. Daydream signer → daydream-byoc. pymthouse signer → pymthouse-live-runner.

2. Enable on NaaP (once)

Default is OFF (404). Turn on for the environment that should serve these bundles.

Vercel / host env
SIGNER_BUNDLE_DISCOVERY_ENABLED=true
ItemValue
Auth Authorization: Bearer gw_… (Service Gateway API key)
Base path /api/v1/orchestrator-leaderboard/bundles
Response Bare JSON array [{ "address": "<orchUri>" }]
Headers X-Discovery-Bundle, X-Discovery-Mode: signer-bundle

3. Configure Daydream signer → BYOC

  1. On the SDK / gateway node that uses the Daydream remote signer, set DISCOVERY_URL to the naap-default-daydream-byoc plan’s python-gateway URL (visible in the Plans UI).
  2. Redeploy / restart the node so it picks up the env.
  3. Smoke-test with the same gw_ key the node will use.
Node env — Daydream path (plan URL)
NAAP_API_URL=https://app.naap.io
NAAP_API_KEY=gw_xxxxxxxx

# Resolve plan id from billingPlanId=naap-default-daydream-byoc (UI: /orchestrator-leaderboard/plans)
PLAN_ID=PLAN_ID_HERE
DISCOVERY_URL=${NAAP_API_URL}/api/v1/orchestrator-leaderboard/plans/${PLAN_ID}/python-gateway

# Alias (requires SIGNER_BUNDLE_DISCOVERY_ENABLED=true):
# DISCOVERY_URL=${NAAP_API_URL}/api/v1/orchestrator-leaderboard/bundles/daydream-byoc/python-gateway
Smoke test
curl -sS -H "Authorization: Bearer $NAAP_API_KEY" \
  "$DISCOVERY_URL" | jq .

# Expect addresses including:
#   https://byoc-staging-1.daydream.monster:8935
#   https://tool-staging-1.daydream.monster:8935
# Header: X-Discovery-Bundle: daydream-byoc

4. Configure pymthouse signer → Live Runner

  1. On the SDK / gateway node that uses the pymthouse per-key DMZ signer (SIGNER_FROM_VALIDATE / validate endpoint form), set DISCOVERY_URL to the Live Runner plan python-gateway URL (naap-default-pymthouse-live-runner).
  2. Redeploy / restart.
  3. Smoke-test; confirm LR host, not BYOC host.
Node env — pymthouse path (plan URL)
NAAP_API_URL=https://app.naap.io
NAAP_API_KEY=gw_xxxxxxxx

PLAN_ID=PLAN_ID_HERE
DISCOVERY_URL=${NAAP_API_URL}/api/v1/orchestrator-leaderboard/plans/${PLAN_ID}/python-gateway

# Alias (requires SIGNER_BUNDLE_DISCOVERY_ENABLED=true):
# DISCOVERY_URL=${NAAP_API_URL}/api/v1/orchestrator-leaderboard/bundles/pymthouse-live-runner/python-gateway
Smoke test
curl -sS -H "Authorization: Bearer $NAAP_API_KEY" \
  "$DISCOVERY_URL" | jq .

# Expect addresses including:
#   https://liverunner-staging-1.daydream.monster:8935
# Must NOT include byoc-staging-1 / tool-staging-1
# Header: X-Discovery-Bundle: pymthouse-live-runner

5. Verify isolation

Both endpoints should return non-overlapping address sets.

Cross-check
BASE="$NAAP_API_URL/api/v1/orchestrator-leaderboard/bundles"
AUTH="Authorization: Bearer $NAAP_API_KEY"

DAY=$(curl -sS -H "$AUTH" "$BASE/daydream-byoc/python-gateway")
LR=$(curl -sS -H "$AUTH" "$BASE/pymthouse-live-runner/python-gateway")

echo "Daydream-BYOC:" && echo "$DAY" | jq -r '.[].address'
echo "pymthouse-LR:"  && echo "$LR"  | jq -r '.[].address'

echo "Overlap count (expect 0):"
comm -12 \
  <(echo "$DAY" | jq -r '.[].address' | sort) \
  <(echo "$LR"  | jq -r '.[].address' | sort) | wc -l

6. Optional — admin overrides

Defaults come from the committed staging baseline. To change categories, static fleet URLs, or topN without redeploying code:

List bundles (admin)
curl -sS -H "Authorization: Bearer $NAAP_ADMIN_JWT" \
  "$NAAP_API_URL/api/v1/orchestrator-leaderboard/bundles/config" | jq .
Override LR static fleet / topN
curl -sS -X PUT \
  -H "Authorization: Bearer $NAAP_ADMIN_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "bundles": [{
      "slug": "pymthouse-live-runner",
      "enabled": true,
      "topN": 50,
      "categoryStaticOrchestrators": {
        "lr": ["https://liverunner-staging-1.daydream.monster:8935"]
      }
    }]
  }' \
  "$NAAP_API_URL/api/v1/orchestrator-leaderboard/bundles/config" | jq .
Ops hotfix without admin UI: set SIGNER_BUNDLE_OVERRIDES='{"bundles":[…]}' on NaaP (env wins over DB). Prefer admin PUT for durable changes.

7. Troubleshoot

SymptomFix
404 Set SIGNER_BUNDLE_DISCOVERY_ENABLED=true and redeploy NaaP.
401 Pass a valid gw_ key or session JWT.
Empty [] Check bundle enabled, pymthouse manifest filter (LR bundle), and static fleet config.
Wrong orch plane Node’s DISCOVERY_URL points at the other slug — swap it.
Still old discovery Search deploy env for stale DISCOVERY_URL / file-based discovery JSON.
