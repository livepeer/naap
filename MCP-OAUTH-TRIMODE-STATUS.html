4.3 Shared mint secret + allowlist

  1. Generate a high-entropy secret (password manager / openssl rand -hex 32).
  2. Set the same value on NaaP Preview MCP_INTERNAL_MINT_SECRET and Storyboard Preview MCP_INTERNAL_MINT_SECRET.
  3. Set NaaP MCP_INTERNAL_MINT_ALLOWLIST to the Storyboard Preview origin(s) you will call from (exact origin match).
  4. Set Storyboard MCP_INTERNAL_MINT_CALLER_ORIGIN to that same origin string.
  5. Confirm PYMTHOUSE_PUBLIC_CLIENT_ID / billing app id is the test app only — mint returns 503 billing_app_mismatch otherwise.

4.4 Flag flip order / stop-line (before MCP_OAUTH_ENABLED=1)

Stop-line checklist (Preview only)

  1. NaaP Preview: M2M id+secret + mint secret + allowlist + test-app public client wired; redeploy.
  2. Verify mint config presence (expect 401 unauthorized with wrong Bearer, not 404): 
    curl -sS -D - -X POST "$NAAP_PREVIEW/api/internal/mcp/mint" \
  -H 'content-type: application/json' \
  -H 'authorization: Bearer wrong' \
  -H "x-mcp-caller-origin: $STORYBOARD_PREVIEW_ORIGIN" \
  -d '{"externalUserId":"ops-probe"}'
# expect: HTTP 401 {"error":"unauthorized"}
# still 404 ⇒ secret/allowlist not loaded — do not flip Storyboard flag
  3. Storyboard Preview: set provider + mint URL + shared secret + caller origin + KV; keep MCP_OAUTH_ENABLED unset; redeploy; confirm broker still 404.
  4. Prod regression tripwire (must stay green): well-known short-TTL 404; broker 404; unbound mcp_at_* 401; demo/no-key 200.
  5. Only then on one Storyboard Preview: MCP_OAUTH_ENABLED=1 and MCP_OAUTH_PROVIDER=naap.
  6. Never set MCP_OAUTH_ENABLED=1 on Storyboard Production until Preview 12-row matrix + one billed test-app call (§2.3.1 bar) pass.

5 · User stories (based on test results)

What this ENABLES now

  • Paste Daydream sk_* — still the primary prod path; Track 1 invariants pin byte-identity.
  • Paste pymthouse composite app_*_pmth_* — classified as pmth-composite (log-only); billing tail unchanged when signer/routing already work for that key.
  • Flag-OFF safety — OAuth broker and PRM/AS discovery stay dark; short-TTL well-known means a future flag flip is not stuck behind 24h immutable CDN cache.
  • Auth Resolution Layer — single mode-selection site; tools/SDK stay auth-agnostic.
  • Unbound mcp_at_* cannot silently bill Daydream — fail-closed 401 verified on prod.
  • oauth-store ready — Upstash-backed binding module merged; used only when broker runs under flag ON.
  • Scenario A code path present — NaaP mint route + Storyboard naap provider on main, inert until secrets + flag.

What becomes possible AFTER ops wire + Preview flag ON

  • NaaP-mediated OAuth (Scenario A): Claude/MCP client discovers AS → PKCE authorize → NaaP identity → internal mint → opaque mcp_at_* → store lookup → composite forwardBearer → inference billed to the test app.
  • Connector “sign in” UX without pasting a key (still Preview until prod promotion).
  • §2.3.1 billed proof on Preview (signer 200 + tickets + asset) without waiting for FU-1 metering reads.

What is STILL NOT SUPPORTED / not possible

  • Prod OAuth login until stop-line + Preview matrix — do not set MCP_OAUTH_ENABLED=1 on Storyboard Production yet.
  • Scenario B (pymthouse-direct OAuth without NaaP) — needs confidential web_ client (OA-5) and PR-14/PR-15; public app_ clients cannot do authorization_code for this design.
  • Metering debit confirmation — FU-1 deferred; cannot claim “usage API shows the charge” yet.
  • LR front-door inference if gateway still lacks live_runner/call_runner (OA-2 / Track 4).
  • Live mint against a customer app — hard-blocked (RS-2); only test app id is accepted.
  • Refresh tokens / long MCP sessions / revocation — N8/N11; short TTL only.
  • OAuth on REST proxy routes — INV-6 / AP-8; MCP entry only.
Legitimate stop-line end state (plan §9). If Preview mint cannot be wired, shipping P0 paste-key + inert OAuth head remains an approved outcome: invariants, resolution layer, composite visibility, durable store, and fail-closed mcp_at_* still have standalone value.
