Dual-Key (Option A) — Enablement How-To

Operator guide for turning on per-key routing on sdk-staging-1 (SDK service behind sdk.daydream.monster). Inspection-verified 2026-07-29. Image sdk-service:optA-lr-multi-dualkey-2026-07-29.

TL;DR

The dual-key image is deployed and every supporting prerequisite is set. All 6 enable flags are OFF, so behavior is byte-identical to the legacy naap_ path. Enabling is a pure .env edit + docker compose up -d sdk-service — no rebuild, no deploy. Roll back by unsetting the flag and re-running up -d.

Run 70 — composite-default cutover

naap_/validate is retired. The pymthouse plane is now driven by the COMPOSITE key (app_*_pmth_*): put the composite key in the MCP key section and inference works with no validate step — the composite bearer is forwarded DIRECT to PYMTHOUSE_SIGNER_URL (validate SKIPPED) by default. Removed vars: AUTH_VALIDATE_URL, SIGNER_FROM_VALIDATE, PYMTHOUSE_COMPOSITE_DIRECT, NAAP_FAIL_CLOSED. Default KEY_PATTERN_PYMTHOUSE is now app_*_pmth_* (no naap_*). The still-relevant knobs are KEY_ROUTING_FROM_ENV=1, KEY_PATTERN_PYMTHOUSE, KEY_PATTERN_DAYDREAM, KEY_ROUTING_UNMATCHED, PYMTHOUSE_SIGNER_URL, ORCH_PIN_BY_PATH.

2 · The 6 flags

Semantics per key_routing.py. All default OFF/empty; with defaults the routing decision is unchanged from legacy. Two independent planes are controlled: the signer plane (which wallet/session signs the job) and the orch plane (which orchestrator family serves it).

FlagValues / defaultEffect when ON
KEY_ROUTING_FROM_ENV 0/unset (def) · 1 Master gate. OFF = legacy naap_-prefix discriminator decides the path. ON = use the CSV pattern engine below. With default patterns, ON is behavior-preserving.
KEY_PATTERN_PYMTHOUSE CSV globs · def naap_* Keys matching any glob are the pymthouse path (dedicated signer + LR plane). Evaluated first. Comma-separated, case-sensitive, first-match-wins.
KEY_PATTERN_DAYDREAM CSV globs · def sk_* Keys matching any glob are the daydream (shared/legacy) path. Evaluated after pymthouse. Same CSV / case-sensitive / first-match rules.
KEY_ROUTING_UNMATCHED fail_closed (def) · daydream What happens to a key matching neither pattern. fail_closed = reject the request. daydream = legacy fall-through to the shared path.
ORCH_PIN_BY_PATH 0/unset (def) · 1 Symmetric orch pin. pymthouse → LR-only, reject on miss (no BYOC fail-open). daydream → BYOC-only. Assumes the pymthouse signer plane is active (SIGNER_FROM_VALIDATE=1); enabling it with the signer plane off classifies all traffic as daydream and excludes it from LR.
NAAP_FAIL_CLOSED 0/unset (def) · 1 For a pymthouse-matched key that resolves no session, reject instead of falling through to the shared wallet. Requires SIGNER_FROM_VALIDATE=1. Disjoint from KEY_ROUTING_UNMATCHED (that one is for keys matching no pattern; this one is for matched-but-no-session).
PYMTHOUSE_COMPOSITE_DIRECT + PYMTHOUSE_SIGNER_URL 0/unset (def) · 1  |  URL empty (def) Composite direct-to-signer (--token style). A pymthouse COMPOSITE bearer (app_*_pmth_*) is the session-output key — it 404s on /keys/validate. When PYMTHOUSE_COMPOSITE_DIRECT=1 and PYMTHOUSE_SIGNER_URL is set, a composite on the pymthouse path skips validate and forwards the bearer straight to the signer as Authorization: Bearer <composite> (mirrors livepeer-python-gateway --token; no session exchange). Off/empty ⇒ composite still RESOLVEs (byte-identical to today). Detection keys on the _pmth_ segment, so naap_ keys always keep RESOLVE.

3 · Setup / enablement order (safe)

Rule

Enable one flag at a time, verify health + a real request between steps, and enable ORCH_PIN_BY_PATH last, one capability / tenant at a time. Instant rollback at every step = unset the flag + docker compose up -d sdk-service.

  1. Confirm the signer is RemoteType_Fixed-capable (per-key fixed-price signing). OQ-1 — prod signer already is; on staging this is provided by SIGNER_FROM_VALIDATE=1 + AUTH_VALIDATE_URL/SIGNER_URL, all set.
  2. Set the patterns + master gate: add KEY_PATTERN_PYMTHOUSE / KEY_PATTERN_DAYDREAM (or accept defaults) and KEY_ROUTING_FROM_ENV=1. With default patterns this is behavior-unchanged — the pattern engine reproduces the legacy split.
  3. Tighten the signer plane: NAAP_FAIL_CLOSED=1 so a matched pymthouse key with no session is rejected rather than borrowing the shared wallet.
  4. Pin the orch plane last: ORCH_PIN_BY_PATH=1, rolled out one cap/tenant at a time. This removes the BYOC fail-open for pymthouse traffic (LR-only, reject-on-miss).

KEY_ROUTING_UNMATCHED stays at its fail_closed default unless you deliberately want legacy fall-through for unmatched keys.

4 · Worked example — full pymthouse-LR lockdown

Target .env additions (everything else on the host stays as-is):

# --- dual-key (Option A) enablement ---
KEY_ROUTING_FROM_ENV=1
KEY_PATTERN_PYMTHOUSE=naap_*
KEY_PATTERN_DAYDREAM=sk_*
KEY_ROUTING_UNMATCHED=fail_closed
NAAP_FAIL_CLOSED=1
ORCH_PIN_BY_PATH=1
# prerequisites (already set on sdk-staging-1):
# SIGNER_FROM_VALIDATE=1 · AUTH_VALIDATE_URL=… · SIGNER_URL=… · LR_ORCH_DISCOVERY=…
