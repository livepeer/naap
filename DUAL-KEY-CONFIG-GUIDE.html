Dual-Key Routing — Config Guide

Six env vars control key→path routing and path→orch pinning in the SDK service. Every one defaults to today's behavior — the service is byte-identical until you opt in. Set them in docker-compose/sdk-service.yaml (passthrough) + the SDK VM's /opt/sdk/.env, then restart the container. All are reversible: unset (or set 0) + restart to revert.

TL;DR. Leave everything unset for today's exact routing. To route real per-key traffic to pymthouse/live-runner and keep Daydream keys on byoc, enable the flags in the order below, one canary instance at a time. Never flip a flag fleet-wide before the canary is green.
Update — Run 70 (composite-default cutover, naap_/validate retired). The pymthouse plane is now driven by the COMPOSITE key (app_*_pmth_*), forwarded DIRECT to the pymthouse signer (PYMTHOUSE_SIGNER_URL) with validate SKIPPED — this is the DEFAULT (no enable-flag). The legacy naap_ front-door / /keys/validate RESOLVE path is retired: AUTH_VALIDATE_URL, SIGNER_FROM_VALIDATE, PYMTHOUSE_COMPOSITE_DIRECT and NAAP_FAIL_CLOSED are gone, and the default KEY_PATTERN_PYMTHOUSE is now app_*_pmth_* (no naap_*). sk_→Daydream static signer and the unmatched policy are unchanged. Shipped in simple-infra#118; live on sdk-staging-1 (image optA-lr-multi-dualkey-compositedefault-2026-07-30).

The flags

1 · KEY_ROUTING_FROM_ENV default 0 (off)

Type: bool 0 | 1. Master gate for the key→path pattern engine.

  • Off (default): the SDK uses the legacy hardcoded rule — a bearer starting with naap_ takes the pymthouse path, everything else takes the Daydream path. Byte-identical to today.
  • On: the bearer is classified by the glob patterns below instead.

2 · KEY_PATTERN_PYMTHOUSE default naap_*

Type: comma-separated glob list. Only read when KEY_ROUTING_FROM_ENV=1. Keys matching any of these globs take the pymthouse / live-runner-eligible path (per-key signer, byoc payment). Evaluated first (wins any overlap).

Example — also route composite provider keys to pymthouse:

KEY_PATTERN_PYMTHOUSE=naap_*,app_*_pmth_*

Glob syntax is fnmatch (*, ?), case-sensitive. No regex.

3 · KEY_PATTERN_DAYDREAM default sk_*

Type: comma-separated glob list. Only read when KEY_ROUTING_FROM_ENV=1. Keys matching any of these globs take the Daydream / byoc path (static SIGNER_URL, lv2v payment). Evaluated second. Covers sk_live_* / sk_test_*.

KEY_PATTERN_DAYDREAM=sk_live_*,sk_test_*

4 · KEY_ROUTING_UNMATCHED default fail_closed

Type: enum fail_closed | daydream. Only read when KEY_ROUTING_FROM_ENV=1. Decides what happens to a key that matches neither pattern list.

  • fail_closed (default): reject the request (401) — never silently bill the shared Daydream wallet.
  • daydream: fall through to the Daydream path (the legacy behavior, if you want it back).

5 · ORCH_PIN_BY_PATH default 0 (off)

Type: bool 0 | 1. One symmetrical switch that pins the orchestrator plane by resolved path.

  • Off (default): pymthouse traffic uses the live-runner orch when the capability is LR-eligible and otherwise fails open to BYOC; Daydream traffic is unchanged.
  • On: the pymthouse path goes to the live-runner orch ONLY (no BYOC fall-open — an LR miss returns 502), and the Daydream path goes to byoc/daydream ONLY (never the live-runner orch).
Prerequisite (OQ-1). Do not enable ORCH_PIN_BY_PATH for the pymthouse path until the pymthouse DMZ signer is RemoteType_Fixed-capable. Removing the BYOC fall-open before that means fal caps would 400 "invalid job type" with no fallback. Until then leave it 0. Also note it only makes sense where the pymthouse signer plane is active (SIGNER_FROM_VALIDATE=1) — with that off, every request is the Daydream path and pinning would exclude all traffic from the live-runner orch.

6 · NAAP_FAIL_CLOSED default 0 (off)

Type: bool 0 | 1. Hardening for the pymthouse path.

  • Off (default): a pymthouse-matched key whose per-key signer session fails to resolve falls through to the static Daydream signer (today's behavior — but it bills the shared wallet: risk R1).
  • On: that request is rejected (402) instead.

Only effective when SIGNER_FROM_VALIDATE=1 (otherwise the signer never resolves a per-key session and this flag is inert). Distinct from KEY_ROUTING_UNMATCHED: that handles keys matching no pattern; this handles a matched pymthouse key with no session.

7 · PYMTHOUSE_COMPOSITE_DIRECT + PYMTHOUSE_SIGNER_URL default 0 (off) / empty

Type: PYMTHOUSE_COMPOSITE_DIRECT = bool 0 | 1; PYMTHOUSE_SIGNER_URL = URL empty. Forwards a pymthouse COMPOSITE bearer (app_*_pmth_*) straight to the pymthouse signer, --token style, skipping /keys/validate.

  • Why: a composite is the session-output bearer a resolved pymthouse session emits. It is not a front-door naap_ key and 404s on /keys/validate, so the RESOLVE path dies and the job falls back to BYOC (the Run 68 gap). This flag sends the composite as a plain Authorization: Bearer <composite> directly to PYMTHOUSE_SIGNER_URL, mirroring livepeer-python-gateway's --token flow — no session exchange.
  • Off (default) or empty URL: a composite still takes the RESOLVE path — byte-identical to today.
  • On + PYMTHOUSE_SIGNER_URL set: a composite on the pymthouse (RESOLVE) path skips validate and signs via the pymthouse signer directly.

Composite detection keys on the _pmth_ session segment, so a front-door naap_ key (no _pmth_) always keeps RESOLVE. Only meaningful when the pattern engine routes the composite to the pymthouse path (KEY_ROUTING_FROM_ENV=1 with app_*_pmth_* in KEY_PATTERN_PYMTHOUSE). Fully reversible: clear PYMTHOUSE_COMPOSITE_DIRECT to revert.

Safe enablement order

Enable per-instance (one canary first), verifying each step before the next. Every step is reversible by clearing the var and restarting.

  1. Baseline. All unset ⇒ production behavior. (This is the state after the three PRs merge.)
  2. Engine, legacy-compatible. On one canary: KEY_ROUTING_FROM_ENV=1 with default patterns and KEY_ROUTING_UNMATCHED=daydream. Verify naap_ and sk_ keys route exactly as before.
  3. Fail-closed unmatched. Flip KEY_ROUTING_UNMATCHED=fail_closed on the canary. Verify unknown keys get 401 and known keys still pass.
  4. Orch pin — only after OQ-1 (DMZ signer is RemoteType_Fixed-capable): ORCH_PIN_BY_PATH=1. Verify naap_→live-runner-only and sk_→byoc-only.
  5. Session fail-closed (optional). NAAP_FAIL_CLOSED=1 (requires SIGNER_FROM_VALIDATE=1).
  6. Promote instance-by-instance once each phase is green.

Quick example — enable the engine on one canary

In the canary SDK VM's /opt/sdk/.env (and make sure the vars are declared in docker-compose/sdk-service.yaml passthrough), then docker compose up -d:

KEY_ROUTING_FROM_ENV=1
KEY_PATTERN_PYMTHOUSE=naap_*,app_*_pmth_*
KEY_PATTERN_DAYDREAM=sk_*
KEY_ROUTING_UNMATCHED=fail_closed
# ORCH_PIN_BY_PATH=1        # only after OQ-1 (fixed-capable DMZ signer)
# NAAP_FAIL_CLOSED=1        # only with SIGNER_FROM_VALIDATE=1

To revert instantly: remove the lines (or set the bools to 0) and restart.
